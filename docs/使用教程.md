# 用 Codex 看懂网站与广告数据

你不需要先学会所有报表。先说清想解决的问题，让 Codex 读取数据、核对口径，再解释该做什么。

## 1. 这几个工具分别看什么

| 工具 | 用日常语言理解 | 能回答的例子 |
|---|---|---|
| 谷歌站长 GSC | 人们在 Google 搜了什么，看到并点击了你哪些页面 | “首页有展示，为什么没人点？” |
| 谷歌分析 GA4 | 访客进站后从哪里来、看了哪些页面、发生了什么行为 | “有人访问，为什么没有咨询？” |
| 谷歌广告 Google Ads | 广告花了多少钱，买来哪些点击，平台记了哪些转化 | “广告费涨了，值得继续投吗？” |

这些数字不能直接混加。一次 Google 搜索点击，不保证对应一次 GA4 访问；一次表单按钮点击，也不保证销售收到一条有效询盘。Skill 会把这些区别解释清楚。

## 2. 第一次安装

在 Codex 中打开一个专门用于客户分析的文件夹，复制下面的请求。把项目选对，后续报告也保存在这里。

```text
请安装 https://github.com/jackzhang1314/b2b-google-analysis-skills 。
先阅读仓库的 README.md 和 install.py。
我需要网站与广告分析，请使用 standard 组合安装到当前项目。
先检查 Python 3.11+ 和文件完整性，再执行安装。
不做全局安装；已有同名不同版本时先保留并说明差异。
安装后检查 5 个 Skill 是否能被发现，并告诉我该怎么开始。
本次只安装 Skill，不修改 Google 账户连接或任何投放设置。
```

只有网站需求，把 `standard` 改成 `ga4-gsc`；只有广告需求，改成 `ads`。安装程序会自动带齐广告模块的相互依赖，不需要你逐个找文件。

**安装完成应看到什么：**Codex 告诉你装在哪个项目、安装了哪些 Skill，且能找到所选的 Skill。看到“复制成功”但无法发现，仍需检查项目位置或重启 Codex。安装成功只证明能力文件就位。

## 3. 安装和连接账户有什么区别

Skill 相当于一套分析方法；账户连接让 Codex 读到你自己的数据。这批 Skill 复用已经授权的只读连接，不自带账号，也不自动新建 Google Cloud 项目。

可以这样检查：

```text
请检查当前项目能否读取我自己的 GA4、谷歌站长和 Google Ads。
只做读取检查，列出能访问的资源名称与网站，确认属于我的业务。
多个账户无法区分时再让我选择。
若缺少连接，说明缺哪一项；有报表可分析的部分继续，不要擅自重建认证。
```

如果尚未连接，你仍可以提供自己的 CSV 或其他平台导出。请保留日期范围、筛选条件和列名。Codex 会告诉你下一份具体需要的报表，不要求你手写 JSON 或把密码、密钥贴进对话。已有一部分数据时先做有依据的分析。

## 4. 先选对入口

| 你的任务 | 使用哪个 Skill | 最少提供什么 | 最后得到什么 |
|---|---|---|---|
| 网站流量、首页关键词、页面与询盘路径 | `$b2b-ga4-gsc` | 网址、主营业务、目标客户、当前问题；GA4/GSC 连接或导出 | 中文 HTML、页面/查询分析、优先行动 CSV |
| 不知道广告哪里有问题，想做整体检查 | `$google-ads-analysis` | 业务范围、目标市场、有效询盘标准；广告连接或导出 | 主要问题、证据、具体操作与验证方法 |
| 已知花费或点击发生变化，想找变化来自哪里 | `$google-ads-diagnose` | 要看的账户与周期、变化现象 | 系列/地区/设备等变化解释、排查顺序 |
| 搜索词跑偏，考虑否定词 | `$google-ads-search-terms` | 做什么、不做什么、竞品词策略；搜索词与现有规则 | 保留、待确认、待审否定和已有覆盖清单 |
| 平台显示很多转化，但销售不认可 | `$google-ads-measurement` | 有效询盘定义；转化动作配置与表现，可选销售反馈 | 各类动作代表什么、哪些已证实、哪些需补证 |
| 希望一份综合 B2B 获客诊断覆盖广告、网站和销售反馈 | `$b2b-google-ads`（可选） | 业务背景；广告数据，已有 GA4/GSC 与销售反馈可补充 | 综合获客诊断、行动表与复盘计划 |

`google-ads-analysis` 是广告套件的总入口，会按问题调用其他三个模块。`b2b-google-ads` 是另一个完整入口，适合希望围绕获客链路组织分析的人。通常选一个广告入口即可，无需让两个入口重复分析同一任务。选择后者时用 `b2b-ads` 安装组合；它不依赖广告套件。

## 5. 四项业务信息就能开始

可以写成一句话，也可以直接提供已有公司介绍：

```text
网址：【你的网址】。
我们主要做：【产品或服务】。
希望吸引：【国家、行业、采购对象】。
这次最想解决：【一个具体问题】。
```

广告任务再说明什么算有效询盘，以及明确不接的业务。不了解账户编号、事件名或报表字段没关系，Codex 应从已连接资源中核对，不让你填写一张技术表。

## 6. 直接复制使用

### 场景一：网站流量下降

自然语言也能用：“帮我看看网站最近流量为什么少了，先告诉我该查哪里。”要固定入口，可以这样写：

```text
请用 $b2b-ga4-gsc 分析【网址】的流量变化。
我们主营【业务】，目标客户是【市场和采购对象】。
先核对最近可用数据，比较两个等长、星期结构可比的周期。
分别解释搜索曝光与点击、进站来源、重点页面和咨询路径。
给我通俗 HTML 报告：最值得处理的三件事、具体页面、怎么改、怎么验证。
如果只是线索而非已证实原因，请说明需要补什么证据。
```

你应得到：下降发生在哪个来源或页面、证据够不够、优先检查什么。数据不足时，结论可以是“先补查”，不能强行找出一个原因。

### 场景二：首页该布局什么关键词

```text
请用 $b2b-ga4-gsc 分析【网址】首页应该重点承接哪些搜索需求。
结合谷歌站长的真实查询词、首页表现、GA4 访问行为和实际网页内容。
区分首页与产品/服务页各自应该回答的问题。
给我可审阅的标题、首屏表达与咨询入口建议，并解释每项依据。
先做分析和草案，不发布网站改动。
```

你应得到：有实际查询依据的页面分工和文案草案。首页有曝光但点击少只是排查起点，不能仅靠一个点击率数字断定页面有问题。

### 场景三：广告费增加，询盘没增加

```text
请用 $google-ads-analysis 只读检查我的广告。
我们主营【业务】，目标地区是【地区】，有效询盘指【采购条件】。
比较合适的两个周期，先核对总花费和转化口径，再找主要变化来自哪些系列。
结合实际搜索词和落地页，给出前三项优先行动。
每项写清发生了什么、怎么做、由谁做、预期帮助，以及做完怎么看。
没有真实销售证据时不要把平台转化写成合格询盘或真实 ROI。
```

已有明确变化对象时可以改用 `$google-ads-diagnose`，例如：“只检查这个系列的点击成本为什么上涨。”最近三天适合发现异常，不等于足以决定长期停投或扩量。

### 场景四：找出需要审查的搜索词

```text
请用 $google-ads-search-terms 审查当前账户的实际搜索字词。
我们做【业务】，不做【明确排除的业务】，竞品词策略是【策略或尚未确定】。
核对本期表现、同系列较长历史、现有否定词和正向关键词。
输出原始搜索词、中文含义、业务理由、拟定范围和误伤风险。
把保留、待确认、建议人工审查、已有规则覆盖分开。
只提供待审表，不把零转化自动当浪费，不写入否定词。
```

你应得到：可以逐项复核的清单。没有历史或业务依据的词会留在待确认；待审 CSV 不是可以直接上传到广告后台的执行文件。

### 场景五：转化数不可信

```text
请用 $google-ads-measurement 核对广告转化。
销售认为有效询盘应符合【条件】，但平台目前记录的转化不清楚代表什么。
分别检查动作设置、系列实际目标和本期表现。
区分平台记录、真实收到、去重有效询盘和销售认可的采购需求。
缺少网站、GTM 或销售证据时，列出具体补查步骤。
只读核验，不改目标、不提交测试表单、不发布标签。
```

你应得到：哪些数字能用于当前判断、哪些需要核验。没有网站或销售权限仍能完成已取得的广告侧检查，但不能因此宣称整条询盘链路已通过。

### 场景六：按完整 B2B 获客链路诊断

先安装 `b2b-ads` 组合，再发送：

```text
请用 $b2b-google-ads 分析我们的 B2B 获客问题。
网站是【网址】，主营【业务】，目标客户【对象】，有效询盘标准【条件】。
这次重点解决【具体问题】。
以广告为主，按需结合已有 GA4、谷歌站长和销售反馈。
解释花费、流量意图、页面承接和询盘质量分别有哪些证据。
交付通俗 HTML 与行动清单；辅助数据缺失的部分明确保留未知。
```

## 7. 拿到报告之后怎么判断完成了

一份有用的报告，至少让你看懂这些内容：

- 分析的是哪个账户或网站、哪两个时期，哪些数据仍可能变化。
- 最值得处理的事情是什么，对生意有什么影响。
- 建议针对哪个页面、系列或搜索词，具体从哪一步开始。
- 哪些是确认的事实，哪些只是可能原因。
- 谁负责行动，做完看哪些结果，什么情况下先别继续调整。

HTML 是给人阅读的报告；CSV 是便于分工和复核的行动清单；详细核验文件留在客户项目中按需查看。脚本生成的空白底稿或几张指标卡，还不等于完成业务分析。

报告提出建议后，可以继续发送：

```text
请把第一项建议拆成我能执行的步骤。
说明起点、需要的最少资料、负责人，以及如何确认完成。
先准备可审阅方案；需要修改网站或广告时，明确列出改动对象与内容。
```

## 8. 下次复盘和升级

复盘时提供上次报告、实际执行了哪些动作、执行日期。只有建议记录而没有实施记录，不能声称某项优化已经产生效果。

```text
请继续使用上次的 Skill 复盘。
这里是上次报告与执行记录：【文件或说明】。
先核对哪些建议已实施，再比较同口径数据。
区分实际改善、同期变化、尚未成熟和仍需补查的部分。
```

升级请求：

```text
请从同一仓库检查并安装最新版，保持当前选择的组合。
先比较同名 Skill；确认来源与文件完整后，用 --upgrade 升级。
旧版完整备份到当前项目的 .agents/skill-backups/，并告诉我备份位置。
不要改其他 Skill、Google 连接或已有客户报告。
```

这批 Skills 帮你读取、计算、解释和准备行动。实际投放与网站改动需要相应工具和具体授权；本仓库不会自动执行这些写入。真实获客效果仍要靠实施记录、销售反馈和后续观察确认。
