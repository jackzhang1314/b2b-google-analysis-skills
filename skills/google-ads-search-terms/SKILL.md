# 搜索字词与否定建议

先读 [数据约定](../google-ads-analysis/references/evidence-contract.md)、[取数指引](../google-ads-analysis/references/mcp-recipes.md) 和 [判断表](references/decision-rules.md)。缺文件先补齐同版本包。

1. **业务边界。** 确认主营服务、地区、采购对象、不做的意图、竞品策略和保护词。未知项不阻碍流量描述，但阻碍相应否定建议。不使用 free / how / repair / competitor 通用黑名单。
2. **取实际字词。** 系列 ID + 原始搜索字词为共同粒度；Search 广告组另取细分。PMax 用 `campaign_search_term_view`，不带关键词相关 segments。不同视图有重叠，不能相加。搜索字词不是投放关键词。
3. **保留历史反例。** 对候选补拉更长窗口（常用 60–90 天，按业务周期调整），注明时区、回补和查询范围。当前与历史都读取 conversions 和 all_conversions；主转化为零但所有转化大于零时，补按转化动作拆分，核验邮箱、联系点击等信号，先留待确认。不能把“本系列不计入主目标”解释成“完全没有转化信号”。跨系列表现不能冒充本系列证据，但可反驳全账户不相关的断言。
4. **取已有规则。** 分别读账户级、系列级、广告组级否定、启用共享清单及挂载关系、正向关键词。清单存在不等于生效；缺一个位置标覆盖未核实。当前配置不代表过去配置。
5. **先合并正确粒度。** 同一系列内分行先汇总，不能丢掉有转化行再建议否定。保留语言、拼写、标点，不自动词干化或合并单复数。
6. **寻找反复出现的意图。** 可用共享脚本生成同系列 1–3 词组观察。组间有重叠，不能相加为浪费总额；词组不是自动否定建议。中文与复杂标点另作语义审查。
7. **分四类。** 保留；需要业务/历史确认；建议人工审查；已有规则覆盖。每条建议含原始字词、理由、范围、误伤反例，不承诺节省。
8. **检查冲突。** 核对正向词和历史价值，区分有意分流与真实问题。字面重叠不能证明整个正向词被封锁。[校验脚本](../google-ads-analysis/scripts/evidence_guard.py) 通过后仍仅为 REVIEW_ONLY。

输出 `negative-review.csv`：原始字词、系列 ID/名称、拟否定文本、匹配方式、作用域、当前/历史数据、业务依据、现有覆盖、保护检查、证据 ID、理由和状态。不生成自动执行脚本。

PMax 否定只影响 Search / Shopping，不是全部渠道，不杜撰资产组否定。可用时通过 Codex Computer Use 查看官方“预览影响”（最多 10 个），不提交保存；这是辅助预测，不是实得收益。界面不可用时保留待核查状态。
