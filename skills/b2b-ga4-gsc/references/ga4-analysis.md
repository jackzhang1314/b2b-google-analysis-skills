# GA4：访客从哪里来，在哪里停下

## 从现象走到原因

先回答访问量有没有变化，再找哪些渠道、页面、国家或设备贡献了变化。大渠道贡献重要，小样本涨幅不优先。把绝对量和比例一起解释，例如“访问多了200次，但有互动的访问少了60次”，不要只写百分比。

全站、自然搜索、付费访问分别使用各自独立总计；品牌与非品牌、产品/服务页与知识文章按有依据的分类。主机名不一致的会员站、测试站、预览站单列。渠道异常可能来自真实活动、标记缺失、采集变化或无效访问；没有更多证据时不定性机器人或欺诈。

## 页面与采购路径

| 线索 | 下一步核验 | 可提出的实验 |
|---|---|---|
| 访问增加，互动比例降低 | 新增来源/市场/设备、同页面历史、测量变化 | 改善新流量与页面的匹配，避免全站重做 |
| 产品页有人看，询盘动作少 | 实际首屏、产品能力与起订量、联系方式、移动端入口 | 在关键位置解释是否能做，提供清楚的咨询下一步 |
| 表单开始多，后台成功少 | 成功/失败事件定义、字段、上传、验证、后台收件 | 减少不必要必填项，提供工程师协助入口；先保留采购筛选价值 |
| 手机表现弱 | 同来源/国家比较、真实手机布局或明确标记的模拟 | 检查遮挡、按钮、文件上传和表单操作，不能只凭跳出率判速度 |
| 知识文章带来大量访问 | 查询是否与实际产品相关、相关服务入口、后续路径 | 对相关内容加有用的产品/服务链接，不把所有文章硬改成报价页 |

每项建议引用准确 URL 和观察到的内容。点击实际 CTA 核对目的地，URL 名称可能与页面实际功能不同。只看当前页面不能复原历史状态，也不能证明导致了期间变化。浏览器模拟不冒充真机/境外测试，错误须说明复现环境；不擅自提交询盘或发邮件。

## 事件与询盘

会话是一次访问，用户是平台识别后去重的访客，事件是动作次数。`keyEvents / sessions` 是每次访问的事件次数，不是有关键事件的访问比例；后者读 `sessionKeyEventRate`，需要特定动作时使用可用的特定事件指标或适当查询。

按 eventName 核对每个询盘相关动作的触发含义。按钮点击、表单开始、前端成功提示、服务器收到、销售确认有效是不同阶段。相近事件数提示应查触发，不证明同一批人重复；不同查询的用户数也不能拼成严格漏斗。正式漏斗需相同人口、顺序和时间窗口的证据。

没有后台/销售反馈时，说“记录到的咨询相关动作”，不要说“真实询盘”。给出最小反馈表：本地询盘编号、是否实际收到/重复、是否匹配主营产品、采购阶段、原因、后续处理；客户联系人保留私有系统。归因未知保留未知，不靠日期或国家猜来源。

## 判断网站优化效果

同时看访问量、实际成功询盘及销售确认质量，不能只追求互动率或按钮次数更高。先核对修改是否发布、日期和范围，再用相同页面/渠道/设备/市场比较；季节、活动和流量结构改变要说明。短期零事件或少量访问不足以判死页面。

Google Ads 数据有现成连接且能解释付费来源时才辅助使用；按可靠 campaign ID 核对，缺失保留。网站诊断不默认需要花费、出价或全账户广告审计。
