# 数据读取与口径

先发现当前工具、参数和身份，不照抄其他 MCP 的工具名。GA4 优先复用 Google 官方 Analytics MCP；GSC 使用已获准的读取工具或官方 API。安装 Skill 不等于授权，连接失败与数据为空分开诊断。

## 最小读取顺序

1. GA4 核对数字属性 ID、网站数据流、时区和生产 hostname；`G-...` 不是 Data API 属性 ID。GSC 核对完整 `siteUrl`，不把网址前缀与网域属性当同一范围。
2. 确定各来源可用日期。GSC 记录实际 `dataState`，默认省略时为 final；查看按日覆盖，缺日不是自动零值。近期临时数据单列。GA4 数据处理和询盘结果的成熟度分别说明，不机械使用固定等待天数。
3. 两期先读独立无分组总计，再按问题下钻。不同来源按各自时区，不能为数字一致而偷偷修改窗口或过滤。
4. 保存请求、返回、实际字段、过滤、分页、行数、处理状态、捕获时间和来源。文件摘要验证本地文件是否变化，不证明归因或业务断言正确。

| 来源 | 独立总计 | 按需下钻 |
|---|---|---|
| GA4 | sessions、totalUsers；可用时 engagementRate、sessionKeyEventRate、keyEvents | sessionDefaultChannelGroup / sessionSourceMedium、landingPage、country、deviceCategory、eventName |
| GSC | clicks、impressions、ctr、position | date、query、page、country、device；首页精确 page 筛选另取独立总计 |

先核验字段兼容性、分页与配额；工具可能使用 snake_case 而官方字段是 camelCase。无维度 GSC 请求可能需省略 dimensions。工具未提供的分页或状态控制不得声称已使用；已有获准 API/CLI 可补验，否则具体标部分覆盖。

## 不静默修数据

- 保留平台原始元数据中的抽样、阈值、其他行、未定稿和截断信息。GSC 即使翻完页也可能只披露部分查询，不能称搜索全量。
- 独立总计不等于逐日/逐设备用户求和。出现不闭合时先核对范围和指标；未解开就保留差异，不能选一份更好看的数字。
- 完整 URL 先保留；按路径合并要另作明确汇总，不覆盖同名行。用户等不可加指标应使用该路径的原生查询，不能合并行后相加。
- 0、null、未返回分别处理。不把 missing 或 `(not set)` 猜为自然/付费、首页或某个系列。
- 403 检查真实资源、权限、API 和参数。不要为一次查询报错重登共享 ADC、扩大权限或扫描别的项目凭据。

## 连接不足时

按客户包里的连接指南处理实际缺少的部分；已有连接保持。没有连接能力时，一次给一个最小导出任务，写清后台入口、日期、过滤和列：

- GA4 先要流量获取或着陆页报表：同长度两期、生产域名、来源/页面、会话、用户、互动率和已配置的关键事件。
- GSC 先要搜索结果表现：搜索类型 Web、两期、点击/曝光/CTR/平均位置；首页问题加精确首页页面过滤，再取查询词。

缺哪份就限制哪部分，继续能完成的工作。不要先让小白导出十张表。
