# 询盘质量与经济性

| 层级 | 最小证据 | 不能代替它 |
|---|---|---|
| 平台转化 | 动作、来源、窗口、计数、系列实际目标 | 合计数或动作名称 |
| 有效询盘 | 真实送达并去重，排除垃圾/重复/测试 | 按钮点击、浏览、事件触发 |
| 合格询盘 | 销售按产品、市场、采购角色、需求/MOQ确认 | 邮箱存在、访问时长、模型评分 |
| 成交与收益 | 订单、净收入/退款、成本和归因口径 | 固定转化价值、Mock CRM、预计金额 |

客户用日常语言定义资格，例如“目标市场的机械 OEM，采购可生产的定制件，符合起订量，有联系方式与明确需求”。例子不能变成所有客户标准。

没有 CRM 就用 `assets/lead-feedback.csv`，每条用非个人信息的本地询盘 ID，由销售填状态和理由，Codex 汇总去重。归因未知保留 unknown，不靠日期接近、国家或邮箱猜系列。姓名/邮箱/电话/gclid/邮箱哈希留私有系统，不进公共报告或示例。该表解决质量反馈，不自动补齐归因。

## 测量核验

“全部转化设置库存”和“当期有表现动作”分开，未返回表现不等于动作不存在或为零。读标准/系列目标与 custom goal 成员；Secondary 可能参与出价。名称仅为线索。

查成功条件、触发次数、原生/GA4导入/离线上传是否重复表达业务结果、计数/窗口、Consent/跨域、实际请求响应、诊断与上传错误。`all_conversions > conversions`、上传状态正常、事件量大都不是端到端通过证明。

实际提交表单、发布标签、上传转化要有具体授权；分析不包含造询盘或发邮件。可先交具体测试与验收步骤。不同来源事件不强行一一对应；缺证不能说成已确认故障。

## 公式与条件

- 平台 CPA = 广告费 / 平台转化，只标平台口径。
- 有效询盘成本 = 同广告归因队列费用 / 去重有效询盘。
- 合格询盘成本 CPQL = 同广告归因队列费用 / 销售确认合格询盘。
- 合格率 = 同已判定队列合格询盘 / 有效询盘；并列未判定比例，不把未成熟队列当最终质量。
- 真实收入 ROAS = 同队列净收入 / 广告费。
- 广告贡献 ROI = (同队列已确认毛利 − 广告费) / 广告费。这不是含全部运营成本的公司净 ROI；完整 ROI 需额外明确增量成本且防止重复扣除。

分母零为未定义，缺失为待补，均不能写成 0。币种、获客队列、交互日/成交日、归因和结案时间要对齐；退款、去重、回传延迟、线索与订单的一对多需说明。

成熟真实队列可做计划：`可接受 CPQL = 合格到成交率 × 平均已确认单笔毛利 × 愿投入广告的毛利份额`。列输入、样本、敏感区间，这是计划假设，不是实际 ROI 或默认出价；缺值不补行业均值。

## 回传计划

只有软事件时，先验证有效询盘和销售反馈，再评估 Qualified lead / Converted lead 与增强型潜在客户转化。列负责人、事件定义、去重键、合法使用与同意、回传延迟、错误监控、上线样例与对账。交付方案不等于上传获准；上传成功不证明匹配正确或利润增长。
