# 报告与优化闭环

先用四句话说花费趋势、可确认的结果层级、核心问题和重要缺证，再给最多三项行动，不先堆指标。

每项行动：事实与来源/范围/日期 → 推断与其他解释 → 具体系列/页面/流程、责任人、先决条件 → 主指标、量/质量/费用护栏、成熟窗口、停止或回滚条件。

动作区分可立即核查、待业务确认、可测试优化。费用降但合格询盘同比例降不自动是进步；数量/质量/成本的取舍说明白。

交付独立 HTML、行动 CSV；搜索词任务另给待审表。以 `= + - @` 开头的数据防电子表格公式注入。原始响应、详细核验 JSON 留私有目录，分发模板不带客户数据、作者制作时间或本机过程记录。

`review.py` 是计算与证据骨架。Codex 必须围绕任务填写有证据的 actions；空 actions 会提示分析未完成，不能把只有表格当完整诊断。程序不抓网站、不验证销售真实性、不执行改投放。

记录改动前状态、具体调整、实施证据/时间、范围、基线与回滚。下次先看行动表，不重复推荐已试失败方案，未执行不算优化效果。比较季节/市场/销售承接/预算/并行改动；优先成熟队列或平台实验。不能隔离因素则称同期变化，不说因果。跟踪修复后的转化增加不一定是实际询盘增加。

不默认安排定时任务；用户主动要求周期复盘才创建自动化。

## 完整审计交付

用户要求“完整跑一遍”时，优先行动最多三项不等于全文只能三张卡。HTML 至少包含：

1. 同口径窗口、独立总计、成熟度与可确认的询盘层级；
2. 费用变化贡献大的具体系列、策略/预算现状、同一动作与较长历史；
3. 搜索意图、可见覆盖、PMax 实际页面与已查否定作用域；
4. GA4 全站/付费的分离、系列和落地页行为、事件与归因缺口；
5. GSC 准确首页查询、两期差异、国家/设备构成及页面布局草案；
6. 每项优化的负责人、先决条件、成本/数量/质量护栏和复测窗口；
7. 已读取/已检查/未覆盖清单和证据索引。业务报告含分析日期范围，分发 Skill 不带客户实测或作者制作时间。

不是每次都必须拉以上所有表；已能回答当前问题便停止扩展。完整审计中无法完成的层必须具体写缺哪项，不能用一句“以后查看”代替已授权且可完成的查询。
